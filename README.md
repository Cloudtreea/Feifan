# 历史对对碰

面向 1920×1200 横屏学练机的历史记忆配对游戏，以及独立教师演示后台。

## 本地数据闭环

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
$env:DEMO_ADMIN_KEY="local-demo-reset"
.venv\Scripts\python app.py
```

启动后访问：

- 学生端：<http://127.0.0.1:5000/student?demoStudent=demo-s2101>
- 教师端：<http://127.0.0.1:5000/teacher>
- 健康检查：<http://127.0.0.1:5000/api/health>

学生端在 HTTP 环境自动启用同步，直接打开 `memory_station.html` 时保持离线单文件模式。教师端在 HTTP 环境读取真实 API，直接打开 `teacher_dashboard.html` 时使用匿名模拟数据。

## 演示流程

1. 打开学生端，用 `demo-s2101` 完成一局 4×4。
2. 在学生端网址末尾加入 `?debug=1`，再在设置中确认“等待上传”为 0，状态为“已同步”。正式学生界面默认隐藏身份、同步诊断、清除记录和成就测试工具。
3. 打开教师端并选择高二年级、高二（1）班。
4. 查看新增对局、板块掌握度以及学生详情中的有效错误与首次翻牌豁免。
5. 断开或停止后端后继续游戏，事件会保留在本地；恢复服务后使用 `?debug=1` 打开学生端并点击“立即同步”。

重置演示学习数据：

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5000/api/v1/demo/reset -Headers @{"X-Demo-Admin-Key"="local-demo-reset"}
```

## 自动化测试

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
```

测试覆盖健康检查、事件幂等、教师接口、重置鉴权，以及“首次未知错配保留原始记录但不扣独立判断正确率”。

当前教学证据状态：

- **证据不足**：尚未覆盖30%的板块知识点，不直接判断为薄弱。
- **暴露薄弱**：覆盖达到30%，但覆盖度校准掌握度低于65分。
- **持续积累**：已有一定覆盖和表现，但尚未达到稳定掌握标准。
- **稳定掌握**：覆盖至少60%，且覆盖度校准掌握度达到85分。

## 题库与评分模型

- 题库版本 3 将六个可玩关系扩充到每组至少24题，并为每题补充单元、专题、高考重要度、认知层级和易混组元数据；升级时保留教师自行录入的自定义题。低重要度题目可以保留在管理页，但不会进入随机抽题。
- 中国古代史不再以背诵朝代建立年份为主要内容，改用课程标准和高考主干范围内的阶段特征、制度演变、经济变化与思想文化。
- 游戏积分与知识掌握度分离。游戏积分按棋盘规模校准有效错误密度，独立判断表现占 90%，速度占 10%；常见表现以750分附近为中心聚集，5×5设置更高的完成鼓励基线，优秀表现仍可自然进入900–1000分且不限制人数。
- 掌握度按知识点生成证据，结合有效错误、3×3/4×4/5×5负荷、认知层级、线索和提示。板块掌握度进一步使用“已测表现 × 知识覆盖度”校准：未遇到内容不判错，以35分中性先验降低低覆盖样本的结论强度；教师判断时必须同时查看覆盖率、证据次数与可信度。
- `question_bank_manifest.json` 保存后端使用的题库版本和各板块知识点总量；自动化测试会将它与学生端内置题库逐项核对，防止覆盖率分母随题库修改而失真。
- 题库内容仍需由历史教师结合所在省份教材、选考要求和最新真题持续复核，本模型不以未经验证的“押题命中率”作为收录依据。

## Render 部署

仓库根目录的 `render.yaml` 会创建一个 Python Web Service 和一个 PostgreSQL 数据库。连接字符串与演示重置密钥通过 Render 环境变量提供，不写入 HTML 或仓库。

部署完成后使用：

- `https://你的服务地址/student?demoStudent=demo-s2101`
- `https://你的服务地址/teacher`
- `https://你的服务地址/api/health`

演示前提前访问健康检查地址完成免费实例预热。本项目的 HTML 文件仍可作为断网备用。
